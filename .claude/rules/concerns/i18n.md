# Internationalization

## Purpose

> PLOG is published in Brazilian Portuguese and English, and anything a reader sees has to exist in both. Astro tells every Astro file which locale it is rendering, and interface text comes from one typed dictionary per locale, so a page never has to carry text for the files below it. Good i18n code here reads the locale in one place, keeps every translatable string in the dictionaries, and makes it obvious at the point of use that a value is translated text. This rule covers how each kind of file gets its language and its text, how dates are formatted, and how a page links to its translation. It does not cover mirroring routes in both locales (`architecture.md`), the casing of locale codes or dictionary file names (`nomenclature.md`), or how posts are written and translated.

## Rules

### ✅ Do

| Rule                                   | Directive                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Read the locale from Astro**         | Get the language in a layout with `toLanguage(Astro.currentLocale)` — Astro computes it from the URL prefix for every page, prerendered ones included, and `toLanguage` fails the build when the value isn't a `Language`.                                                                                                                                                                 |
| **Keep text in both dictionaries**     | Add every translatable string, `aria-label` and `title` values included, to `Strings` in `src/types/i18n.types.ts` and to both `pt-br.ts` and `en-us.ts`; only language names stay in `getLanguageDetails`, written once in their own language — both dictionaries are typed by `Strings`, so a key added to one language and not the other fails type checking instead of shipping blank. |
| **Name the dictionary strings**        | Assign the whole dictionary with `const strings = getStrings(language)` and read `strings.header` or `strings.home.title` — the `strings.` prefix says at the point of use that the value is translated text.                                                                                                                                                                              |
| **Separate props from the locale**     | Declare `language` and `strings` after the `Astro.props` destructuring, with a blank line between them — props come from the caller and the locale comes from the URL, and the blank line keeps the two sources visibly apart.                                                                                                                                                             |
| **Hand components their text**         | Pass a component the `language` and the slice of `strings` it renders, typed as a part of `Strings` such as `Strings['search']`, from the layout or component that renders it — Preact components can't read the `Astro` global, and Astro components take the same props so that every component renders whatever language it is given.                                                   |
| **Build layout links with Astro**      | Create locale URLs in layouts with `getRelativeLocaleUrl` from `astro:i18n`, as the home link and the home alternates do — the helper follows the `i18n` config, so a change to prefixes or trailing slashes can't leave a hand-built link behind.                                                                                                                                         |
| **Give the layout every alternate**    | Pass `BaseLayout` an `AlternateLanguageLinks` with one URL per language, each pointing at the same page in that language — `BaseLayout` turns it into the `hreflang` links and the header's language switch, so a wrong entry breaks both.                                                                                                                                                 |
| **Format dates for the page language** | Render dates with `toLocalizedDate(date, language)` — a bare `toLocaleDateString()` uses the locale of the build machine or the visitor's browser, so the same post shows a different format on each.                                                                                                                                                                                      |

### 🚫 Don't

| Rule                           | Directive                                                                                                                                                                                                                                                         |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **No hard-coded text**         | Don't write translatable text as a literal in a page, layout or component; add it to the dictionaries instead — a literal renders in one language on both locales, and nothing flags it.                                                                          |
| **No destructured strings**    | Don't destructure the dictionary into `header`, `home` or `title` — a bare `header` reads like an element and a bare `title` like a prop, so the reader can't tell translated text from markup.                                                                   |
| **No locale from the browser** | Don't read the locale from `window.location`, `navigator.language` or by parsing `Astro.url`; use `Astro.currentLocale` or a `language` prop — `window` doesn't exist while Astro renders on the server, and URL parsing duplicates a rule Astro already applies. |
| **No text passed from pages**  | Don't pass interface text from a page to its layout; pages pass data such as posts, and the layout reads its own text — page-passed text has to be repeated in every page of a locale and drifts between them.                                                    |

## Reference

### Where each file gets its language and text

| File                                 | Language                                                                                         | Text                                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| Page in `src/pages/<locale>/`        | Its folder, written as the literal it passes to services, such as `getHighlightedPosts('pt-br')` | None; it passes data only                                                                    |
| Root page (`404.astro`, `500.astro`) | None; its layout gets the default locale, Portuguese, from `Astro.currentLocale`                 | None                                                                                         |
| Layout                               | `toLanguage(Astro.currentLocale)`                                                                | `getStrings(language)`                                                                       |
| Astro or Preact component            | A `language` prop                                                                                | A `strings` prop typed as a part of `Strings`                                                |
| Util                                 | A `language` parameter                                                                           | None; only `getLanguageDetails` holds text, the language names written in their own language |

## Patterns

### ✅ Correct

```astro
---
type Props = {
  highlights: Post[]
  recents: Post[]
  posts: Post[]
}

const { highlights, recents, posts } = Astro.props

const language = toLanguage(Astro.currentLocale)
const strings = getStrings(language)

const alternates: AlternateLanguageLinks = {
  'pt-br': getRelativeLocaleUrl('pt-br'),
  'en-us': getRelativeLocaleUrl('en-us'),
}
---

<BaseLayout
  title={strings.home.title}
  description={strings.home.description}
  alternates={alternates}
>
  <SearchMenu
    client:only="preact"
    posts={posts}
    enabled={false}
    language={language}
    strings={strings.search}
  />
  <h1>{strings.home.heading}</h1>
  <h2>{strings.home.highlights}</h2>
  <HomePostList posts={highlights} language={language} />
</BaseLayout>
```

### 🚫 Wrong

```astro
---
const { highlights, posts } = Astro.props
const { home, search } = getStrings('pt-br')
---

<BaseLayout title={home.title} alternates={{ 'pt-br': '/pt-br/', 'en-us': '/en-us/' }}>
  <SearchMenu client:only="preact" posts={posts} enabled={false} strings={search} />
  <h2>Destaques</h2>
  <HomePostList posts={highlights} language="pt-br" />
</BaseLayout>
```

> The hard-coded `'pt-br'` renders Portuguese text and dates on the English page, and `Destaques` stays Portuguese on both locales. The destructured `home` and `search` read like a page and a feature instead of text, and without the blank line the props and the locale blur into one block. The search island gets no `language`, so it can't format dates or preselect the page's language, and the hand-written alternates skip the `i18n` config.
